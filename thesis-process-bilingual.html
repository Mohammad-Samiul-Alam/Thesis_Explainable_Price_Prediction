1Inspect the data

Before any work, learn what the data holds and where it is messy.

What to do

Load raw.csv, count rows and columns, and check how much is empty in each column.

Why

Running a model on data you have not checked gives wrong results.

How
df = pd.read_csv("raw.csv")
print(df.shape)          # (6504, 13)
print(df.isna().sum())   # where it is empty
print(df.platform_name.value_counts())
Example
Pickaboo has 4,536 rows, Daraz 1,959, and 9 rows are broken. platform_name is filled only for Pickaboo.
Result
A list of what is fine and what needs fixing.

2Clean the data

Turn raw data into something a machine can read.

What to do
  • Drop 9 broken rows (review text broke the CSV and landed in product_url).
  • Drop 506 rows with no price.
  • Drop 31 duplicate URLs and repeated products.
  • Convert price text to numbers.
  • Drop the reviews column (junk).
Why

"৳ 3,049" is text, and a model needs a number. Broken rows and duplicates distort the results.

How
df = df[df.product_url.astype(str).str.startswith("http")]
num = lambda s: pd.to_numeric(
    s.astype(str).str.replace(r"[^\d.]", "", regex=True), errors="coerce")
df["price"] = num(df.discounted_price).fillna(num(df.listed_price))
df = df[df.price.notna()].drop_duplicates("product_url")
Example
"৳ 3,049" becomes 3049. Row 82 had 22"" as its product_name, so it is dropped.
Result
6,504 rows become about 5,958 usable rows (Pickaboo 4,058, Daraz 1,900). This script is your reusable pipeline.

3Set the target and avoid data leakage

The most important decision: what to predict, and what not to feed in.

What to do

Target = final price (discounted_price, or listed_price when there is no discount). Remove listed_price and discount_percent from the inputs.

Why

Listed price and discounted price correlate at 0.98. Giving the model a near copy of the answer makes it cheat.

Get this wrong and R² looks fake-good, which weakens the whole thesis.
How
y = df["price"]
drop = ["listed_price","discount_percent","discounted_price"]
X = features.drop(columns=drop, errors="ignore")

Alternative: keep discount as a feature and use listed_price as the target. Either way, write down the reason in the thesis.

Example
Anker earbuds: listed ৳3,390, discount -10%, discounted ৳3,049. With ৳3,390 as an input, ৳3,049 is easy to guess, but that is looking up the answer, not learning.
Result
A clean target and a leakage-free list of inputs.

4Use log price

A way to handle huge differences in price.

What to do

Train the model on log(price) instead of price.

Why

Prices run from ৳2 to ৳5,99,000 with a median of ৳1,371. A few expensive laptops pull the whole model toward them. Skewness is 8.7 on raw price and 0.49 on log price.

How
y_log = np.log(df["price"])      # what the model learns
pred_taka = np.exp(pred_log)      # convert back to taka
Example
৳1,000 and ৳100,000 differ 100 times. In log terms they are 6.9 and 11.5, much closer.
Result
More stable training. Back the choice with the skewness numbers in the thesis.

5Create features (feature engineering)

Build useful information from the raw columns. This is where most of the model's quality comes from.

What to do
FeatureWhere it comes from
PlatformWhether the URL has pickaboo or daraz
CategoryKeywords in the name: laptop, earphone, charger...
BrandBrand column, rare brands grouped as "Other"
Warranty"18 Months..." becomes 18 months
Description lengthCharacter count of the description
SpecsGB, RAM, mAh, watt, inch pulled out with regex
Why

A model cannot read a raw product name, but it understands category = laptop.

How
df["platform"] = np.where(df.product_url.str.contains("pickaboo"),
                          "Pickaboo", "Daraz")
df["dlen"] = df.product_description.fillna("").str.len()
df["ram_gb"] = df.product_name.str.extract(r"(\d+)\s*GB", expand=False)
Careful
Daraz is 92% "No Brand" and its warranty is effectively unknown. Rating is about 60% empty, so it is not a main feature. The category rule leaves 1,335 rows as "other", so improve the rule.
Result
One clean row of features for each product.

6Split the data (train/test)

Keep some data aside to test the model honestly.

What to do

80% for training, 20% for testing. Turn categorical columns (brand, category) into numbers.

Why

Testing on data the model already saw always looks good, and that is misleading. The same product on both sides causes the same problem.

How
from sklearn.model_selection import GroupShuffleSplit
gss = GroupShuffleSplit(test_size=0.2, random_state=0)
tr, te = next(gss.split(X, y_log, groups=df.product_name))
Result
Separate train and test sets. Run cross-validation on top.

7Train three models

From simple to complex: compare three kinds of model.

What to do
ModelWhat it does
Linear RegressionSimple direct relationships, the baseline
Random ForestAverages many decision trees
XGBoostLearns by correcting its own mistakes, captures complex patterns
Why

If a simple model gives nearly the same result, the complex one is less needed. You cannot name a best model without comparing.

How
models = {"LR": LinearRegression(),
          "RF": RandomForestRegressor(300, random_state=0),
          "XGB": XGBRegressor(n_estimators=400, learning_rate=0.05)}
for name, m in models.items(): m.fit(X.iloc[tr], y_log.iloc[tr])
Example
Quick baseline: Ridge R² 0.61, Random Forest R² 0.71. XGBoost has not been run yet.
Result
Three trained models.

8Evaluate the models

Show with numbers which model is best.

What to do
MetricMeaning
MAEAverage error in taka
RMSEPunishes big mistakes more
R²How much of the price variation is explained
Why

Laptop prices run into the lakhs, so MAE in taka is dominated by laptops. Report both log scale and taka, and break results down by category.

How
p = m.predict(X.iloc[te])
mae = mean_absolute_error(np.exp(y_log.iloc[te]), np.exp(p))
r2  = r2_score(y_log.iloc[te], p)
Example
Actual ৳30,000 and predicted ৳28,000 is an error of ৳2,000.
Result
A comparison table and the choice of best model.

9Explain with SHAP, and state limitations

The "Explainable" part of the thesis and its main novelty.

What to do
  • Summary plot: which features matter most overall.
  • Dependence plot: how price changes as one feature changes.
  • Waterfall plot: a separate explanation for 3-4 products.
Why

"The price is ৳35,000" is not enough. Saying why it is ৳35,000 is what sets your thesis apart.

How
import shap
ex = shap.TreeExplainer(best_model)
sv = ex(X.iloc[te])
shap.summary_plot(sv, X.iloc[te])
shap.plots.waterfall(sv[0])
Careful
Brand and platform overlap (Daraz = No Brand), so keep that in mind when reading SHAP. Do not assume a feature ranking in advance; let the results decide it.
Limitations
  • These are listing prices, not actual sale prices.
  • The data is a single snapshot.
  • Daraz lacks brand and warranty information, so platform comparison is not fully fair.
  • The data is mostly accessories, so the scope is "consumer electronics, accessories and devices".
Result
A predicted price plus how much each feature contributed to it.
